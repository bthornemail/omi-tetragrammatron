# METATRON

Status: active scribe/projection guardrail

Metatron is the scribe-transducer of validated Omi-Ring carry-forward states.

It is not the validator.
It is not the cause of transition.
It is not only the renderer.
It is not carrier I/O.

Metatron is the reference-defining observer at the boundary where change becomes visible. It reads Tetragrammatron-validated state and adapts the invariant `omi---imo` relation into notation, geometry, and projection surfaces without accepting or mutating state.

Canonical lock:

```text
Tetragrammatron carries the lawful fold.
Metatron notices the crossing.
Omnicron holds the horizon.
Omi-Ring witnesses the relation.
```

## Name And Mathematical Role

The name Metatron resolves in this framework as the scribe of apparent difference.

The assignment is pattern-first. `0xAA55` is not Metatron because of its
numeric magnitude. It fits Metatron because its bit arrangement combines
balance, complement, alternation, inversion, and visible crossing points in
one bounded witness.

The central witness is:

```text
0xAA55 = 1010 1010 0101 0101
0x55AA = 0101 0101 1010 1010
```

Both are balanced 16-bit witnesses:

```text
8 one bits
8 zero bits
complementary halves
alternation inside each half
no majority bias toward high or low
```

The protocol reading is:

```text
0xAA55  Metatron alternating witness
0x55AA  inverse alternating witness
```

This is not null.
This is not full.
This is not the fold/carry motion.
This is not validation.

It is contrast fitted into a balanced reference pattern. A uniform all-zero
field exposes no internal contrast. A uniform all-one field exposes no
internal contrast. The paired alternating halves make high and low repeatedly
distinguishable, while their crossing seams give that distinction a reference
boundary. That is why Metatron is the scribe: it records where a difference
becomes observable without causing the difference.

## Why The Pattern Fits

For:

```text
W = 0xAA55 = 1010 1010 | 0101 0101
```

the exact bit invariants are:

```text
popcount(W)       = 8
zero-count(W)     = 8
complement(W)     = 0x55AA
byte-swap(W)      = 0x55AA
rotate-8(W)       = 0x55AA
bit-reverse(W)    = W
```

The two bytes are inverse metronomes:

```text
0xAA = high-first alternation
0x55 = low-first alternation
```

Read as a ring, `0xAA55` is not the featureless alternator `0xAAAA`. It has two
deliberate seams:

```text
...0 | 0...  low/low seam
...1 | 1...  high/high seam at ring closure
```

Those seams are themselves balanced: one low seam and one high seam. The
result is a crossed metronome. It alternates within each half, reverses its
phase across the crossing, and preserves equal high and low occupancy over the
whole ring.

This is the sense in which Metatron is perfectly balanced:

```text
not perfect uniformity
not uninterrupted cyclic alternation
not numerical authority

perfect complement balance
perfect mark/hole balance
balanced crossing references
```

`0xAAAA` is a purer cyclic alternator, but it does not encode the same
high-first/low-first crossing. `0xAA55` is the better Metatron witness because
Metatron is not only a beat. Metatron is the observer and scribe of the point
where the beat crosses into its inverse.

Short doctrine:

```text
Metatron is projection as observational reference.
Metatron records the crossing without ruling over it.
Metatron witnesses after validation.
```


Metatron is not the owner of every value in this family. The family is a

Metatron does not accept state. It does not validate truth. It does not mutate citation identity. It does not own files, network, browser ports, or hardware transport.

Metatron may scribe only after a candidate has become validated carry-forward state.

## Relation To Tetragrammatron

Tetragrammatron and Metatron are deliberately separate.

```text
Tetragrammatron
  governs lawful fold/carry transition
  0x3C -> 0x78

Metatron
  witnesses the crossing as balanced alternation
  0xAA55 <-> 0x55AA
```

The Tetragrammatron decides whether a transition may carry forward. Metatron makes the resulting transition readable from a surface.

Therefore Metatron must never be used as a shortcut for validation:

```text
candidate state -> Metatron
```

is invalid.

The lawful path is:

```text
candidate state
  -> Tetragrammatron validation
  -> validated carry-forward state
  -> Metatron scribe/projection
```

Corrected compass:

```text
Omnicron holds the null/full horizon.
Tetragrammatron governs lawful transition.
Metatron scribes the observable crossing.
OMI names the relation.
IMO carries the mirror.
The Omi-Ring witnesses.
```

## Scribe Role

Scribing means deterministic validated-state-to-notation transduction.

A validated relation may be adapted into:

- CONS / CAR / CDR declaration forms
- OMI-Lisp notation
- geometry
- barcode carrier descriptions
- DOM or portal surfaces
- GPIO or hardware projection declarations
- symbolic notation
- projective surface records

Rendering is one output of scribing. Geometry projection is one surface family. The scribe role is broader: it names the boundary between validated relation and projected form.

## Omi-Surface And Fiber Reading

Metatron projects surfaces, not metadata.

OMI does not treat a validated relation as:

```text
data + description
```

It treats it as:

```text
relation + projection
```

The relation stays invariant. The selected surface changes.

Readable model:

```text
validated Omi-Ring state
  -> surface selection
  -> Metatron transduction
  -> notation / geometry / symbolic projection
```

The surface is a fiber over the validated relation. Polybius, Karnaugh, Smith, Betti, Schlaefli, barcode, DOM, SVG, OBJ, glTF, and future surfaces may all expose the same carry-forward state from different bases. None of those surfaces becomes authority by appearing.

This is active V0 code, but it is not the full Omi-Surface registry or full OMI-Lisp declaration runtime.

## V0 Projection Gate

Metatron Scribe V0 reads stored validated-state ring entries.

The gate is intentionally stricter than "candidate exists":

```text
validated-state object -> ring entry -> Metatron scribe record
```

Metatron must reject candidate-only objects. A `RingSlot` must contain a stored validated-state record before Metatron marks it validated or scribable. Legacy metadata-only slots are not projection inputs.

Metatron does not validate.
Metatron does not store.
Metatron does not serialize.
Metatron does not perform browser, network, hardware, or filesystem effects.

## V0 Technical Debt

`core/omicron.c` currently uses local bridge declarations for `--scribe` integration because it remains a legacy monolithic source and cannot yet include the modular Metatron headers cleanly without conflicts.

This is acceptable for V0.

Future refactor target:
unify `core/omicron.c` with the modular `core/metatron.h` API so the CLI does not duplicate declarations.

## Future Runtime Contract

The full Metatron runtime should:

- read only validated Omi-Ring state
- read stored validated-state ring entries before projection/scribing
- select declared notation/surface readings
- emit deterministic symbolic or geometric projection records
- keep validation in Tetragrammatron
- keep carrier I/O in IMO
- deny side-effect projection before validated carry-forward state
